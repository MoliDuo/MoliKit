# 架构

## 是什么

放 Moli 各仓库共用、且可以公开的东西。现在只有 GitHub Actions 的步骤；以后设计令牌和图标、检查工具等，可以公开的也放这里，按目录分。

## 为什么有这个仓库

GitHub 要求被引用的仓库对引用者可读。规范所在的 MoliSpec 是私有的，公开的应用仓库读不到它，所以共用的步骤放在这个公开的仓库里。MoliSpec 仍然私有，里面的调研、登记表、用户名等内部信息不会因此公开。

## 为什么是“步骤”（composite action），不是“可复用的 workflow”

- 可复用 workflow 会让检查的名字变成“调用者任务名 / 被调用任务名”，而规范要求闸门就叫 `ci-gate`，仓库的分支规则和部署触发都认这个固定名字。
- 步骤式的引用不改变任务名：每个应用仓库的 `ci.yml` 仍然自己写任务（`check`、`gitleaks`、`ci-gate`），只是把里面重复的逻辑换成一行引用。应用特有的检查（安装、构建、测试）留在各仓库。

## 约定

- 步骤的名字、输入、输出是接口，只增不改；要改名，新增一个、保留旧的一段时间。
- 引用方固定到提交哈希，版本用 `vX.Y.Z` 标签（规范 006）。
- 这里不放任何私有或内部信息；需要这类值的步骤，让调用方当作输入传入。
- 密钥只能由调用方作为输入传入；这些步骤自己读不到调用方的密钥。
